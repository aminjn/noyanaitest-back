- [x] **F-02** — File upload accepts any content type; filename handling is path-traversal-capable. Repo: back (`Controllers/uploadController.ts`). Doc: `10_SECURITY_FINDINGS.md` Finding 10.1.
  - **Fix:** `saveUplaodsToBody` no longer trusts `originalname`/`mimetype` at all. - [x] **F-03** — Wallet debited before the record it pays for exists, no rollback, in `bookingController.ts:submitBookingNew` and `CartController.ts` checkout. Repo: back. Doc: `09_FAILURE_PATHS.md` Finding 9.1.
  - **Fix (no DB transaction — topology unconfirmed, see finding's own caveat):** reordered both flows to create the record first (`Reservation`/`Order`, the latter in `status: "pending"`) *before* touching the wallet, so a failure in record creation never touches money. The debit itself is now atomic and race-safe (`Wallet.findOneAndUpdate` with a `balance: { $gte: price/total }` filter in the same update, closing the read-then-write race the old two-step check-then-decrement had). If the debit fails (insufficient funds, including the race case), the just-created record is deleted and a normal error is returned. The remaining step (`Transaction.create` + linking it back to the record, `Order` flips to `"paid"` at this point) is wrapped in try/catch: on failure, the wallet is refunded and the record deleted (compensating rollback) before rethrowing, so `catchAsync` forwards the error to the client — no more silent orphaned debits with no `Transaction`/`Reservation`/`Order` to show for them.
  - **Files:** `Controllers/bookingController.ts:submitBookingNew`, `Controllers/CartController.ts:submitCart`.
  - **Not done:** true multi-document Mongo transactions (would need confirming the deployed DB is a replica set — audit flagged this as unverified, still unverified here); a reconciliation job to catch any pre-existing orphaned debits from before this fix.
